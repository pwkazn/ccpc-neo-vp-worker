# CCPC Neo VP

**基于 RankLand 榜单数据的 CCPC 新赛制「实时榜单」模拟器。**

开一场 VP：选比赛 → 定开赛时刻 → 倒计时 → 看榜单实时长出来。做题本身在别的平台（QOJ、牛客、PTA 等）进行，本工具只负责把 RankLand 已有的历史榜单数据，按真实提交时间轴重新「放」一遍，并严格套用 CCPC 新榜单模式的题号显示与题目排序规则。

```
npm run start          # 或 nix run .
# 打开 http://127.0.0.1:5173
```

---

## 它做什么 / 不做什么

| 做 | 不做 |
| --- | --- |
| 列出 RankLand 上 434 场有榜单数据的比赛，搜索选择 | 不提供提交、评测、题目页面 |
| 设定开赛时刻，秒级倒计时后进入实时榜单 | 不代替你在别的平台做题 |
| 按真实提交时间轴逐条回放：AC 数、总罚时、每题提交次数 | 不写入、不上传任何数据到 RankLand |
| 复刻新赛制：题号门限揭示、每队独立的题目列顺序 | 暂无气球功能（数据结构已预留） |
| 自动封榜 / 结束揭榜，可一键切换「全程真实」 | 不做多用户、账号、公网部署 |

## 快速开始

### 只用 Node（推荐，零依赖）

需要 Node **≥ 20**。项目没有任何 `dependencies`，不需要 `npm install`，也不需要构建步骤。

```bash
node server/index.mjs
# 或
npm run start
```

启动后终端会打印实际地址（默认 `http://127.0.0.1:5173`，端口被占用时自动顺延）。

### 用 Nix（NixOS）

```bash
nix run .                   # 启动服务
nix run . -- --port 8080    # 传参数
nix run .#test              # 跑测试
nix run .#test-e2e          # 跑真实数据回归（需要网络）
nix develop                 # 开发环境（node + jq + curl）
nix flake check             # 跑离线测试
```

> **沙箱提示**：如果你的环境里 `~/.cache/nix` 不可写（例如被只读挂载），
> 先 `export XDG_CACHE_HOME=$(mktemp -d)`，否则 `nix shell` / `nix build` 会报
> `unable to open database file`。

### 命令行参数

```
--port <n>        监听端口 (默认 5173，被占用自动顺延)
--host <addr>     监听地址 (默认 127.0.0.1)
--data-dir <dir>  缓存目录 (默认 $XDG_CACHE_HOME/ccpc-neo-vp)
--base-url <url>  RankLand API 基地址 (默认 https://rl.algoux.cn/api/v2)
--verbose         打印每个上游请求的详情（排查网络问题时使用）
--clear-cache     清空缓存后退出
--cache-info      打印缓存占用后退出
-h, --help        帮助
```

环境变量：`PORT`、`HOST`、`CCPC_NEO_VP_DATA_DIR`、`RL_BASE_URL`、`RL_CONNECT_TIMEOUT_MS`、`RL_STALL_TIMEOUT_MS`。

### 网络排查

榜单文件约 2.5 MB，走代理/TUN 或较慢的线路时下载可能很慢。本工具**不设总时长超时**（慢不等于坏），只检测两种情况：

- **连接超时**（默认 30 秒收不到响应头）
- **读取停滞**（默认 45 秒没有新数据）

两者都可以放宽后重启：

```bash
RL_CONNECT_TIMEOUT_MS=60000 RL_STALL_TIMEOUT_MS=120000 nix run . -- --verbose
```

启动时可以随时自检，它会逐步测试「比赛列表 → 文件元信息 → 榜单下载 → 时间线构建」并报告每步耗时与错误：

```bash
curl "http://127.0.0.1:5173/api/diagnose?uk=ccpc2026preliminary"
```

```jsonc
{"steps":[
  {"name":"listContests","ok":true,"ms":299,"contests":434,"found":true},
  {"name":"ccpc2026preliminary.srk.json","ok":true,"ms":51,"size":2591190,"url":"…"},
  {"name":"downloadSrk","ok":true,"ms":438,"bytes":2504556},
  {"name":"buildTimeline","ok":true,"ms":471,"teams":2170,"problems":14,"events":30963,"exact":true}
]}
```

页面上的「加载失败」也会带上**具体原因**（例如「连接 … 超时（30 秒内未收到响应头）」而不是含糊的 “The operation was aborted.”），并在提示里给出上面这个自检地址。

## 网页里的操作

**① 准备页**：搜索比赛（支持名称与 `uk` 模糊匹配），选择开赛方式（倒计时后开赛 / 指定绝对时刻）、封榜模式、题号门限的统计范围。

**② 倒计时页**：大号倒计时，可「立即开始」或取消。

**③ 榜单页**：

- 顶部：比赛名、阶段徽标（等待开始 / 进行中 / 已封榜 / 已结束）、榜单文件来源。
- 播放条：比赛时间 `H:MM:SS`、总时长、墙上时钟、进度条（可拖动跳转）、暂停/继续、倍速 1/2/5/10/60/300x、回到实时、揭榜。
- 过滤条：队伍/学校筛选（高亮）、是否仅官方队伍参与排名、当前显示队数。
- 快捷键：`空格` 暂停/继续，`←/→` 前后跳 60 秒。

**封榜模式**（设置里随时可切换，也会写进初始选项）：

- **自动**：按该场榜单的冻结时长，在最后 1 小时封榜；VP 到终点后自动揭榜，显示真实最终榜单。冻结时长为 0 的场次（如 2026 CCPC 网络预选赛）全程真实。
- **关闭封榜**：榜单全程实时更新，不冻结。

**倍速与拖动**是调试/预习用的：想在 30 秒内看完 5 小时的榜单变化，把倍速拉到 300x 即可。

**可收藏的 URL 参数**：一场 VP 的全部设置都会同步到地址栏，刷新或收藏后直接回到同一场。开局后地址栏形如：

```
http://127.0.0.1:5173/?uk=ccpc2026preliminary&start=1790785531000&freeze=auto
```

| 参数 | 含义 |
| --- | --- |
| `uk` | 比赛唯一键（必填即跳转） |
| `start` | 开赛时刻，Unix 毫秒或 ISO 字符串 |
| `delay` | 相对倒计时秒数（未给 `start` 时生效） |
| `speed` | 倍速，取值 1 / 2 / 5 / 10 / 60 / 300 |
| `freeze` | `auto`（默认）或 `never` |
| `scope` | 题号门限统计范围：`all`（默认）或 `official` |
| `official` | `0` 表示非官方队伍也参与排名 |
| `start_now` | `1` 表示忽略倒计时直接进入榜单 |

例如「直接从第 16 分钟开始看」：

```
?uk=ccpc2026preliminary&start=$(($(date +%s) - 1000))000
```

## 数据来源与 API

数据全部来自 RankLand（<https://rank.ac>，实际站点为 <https://rl.algoux.cn>）的公开只读接口，无需鉴权：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v2/public/contests` | 全部 434 场比赛的元信息（`uk`、名称、开始时间、时长、冻结时长、`srkFileID`） |
| `GET /api/v2/public/contests/:uk` | 比赛详情（题目 alias / 标题 / 颜色 / 链接） |
| `GET /api/v2/public/files/:id` | 榜单文件元信息（含下载 URL 与 sha256） |
| `https://cdn.algoux.cn/rankland/file/...` | 榜单文件本体（Standard Ranklist JSON） |

榜单文件格式是 **Standard Ranklist (SRK) v0.3.13**，规范见 [algoux/standard-ranklist](https://github.com/algoux/standard-ranklist)。

服务端做三件事：抓取、把 SRK 归一化成一份紧凑的「时间轴」、按 sha256 缓存到磁盘。第二次打开同一场比赛是秒开（纯本地缓存读取，无网络请求）。

**缓存位置**：`$XDG_CACHE_HOME/ccpc-neo-vp/`（默认 `~/.cache/ccpc-neo-vp/`），含 `contests.json`、`srk/`、`timeline/`。用 `--cache-info` 看占用，`--clear-cache` 清空。

## 两种榜单数据形态与降级说明

RankLand 上的榜单文件分两类，工具都能处理，但**精度不同，网页会明确提示**：

| | **精确格式**（新） | **旧格式**（降级） |
| --- | --- | --- |
| 特征 | `statuses[].solutions[]` 带每条提交的独立时间戳 | `solutions` 为空，只有该题汇总（`result`、`tries`，可能没有 `time`） |
| 例子 | `ccpc2026preliminary`、`icpc2024preliminary-*`、`ccpc2025preliminary` | `ccpc2017qinhuangdao`、`icpc2018qingdao`、`icpc2020preliminary-xiaomi-*` |
| 回放粒度 | 逐条提交 | 按已公布解题/被拒时刻跳变 |
| 榜单 AC 数、总罚时 | 与官方完全一致 | AC 数准；罚时由 `tries` 近似 |
| 题目排序中的「最晚提交时刻」 | 精确 | **不可知**，退化为按题号排序 |
| 网页提示 | 无 | 顶部显示「排序降级」徽标 |

降级不会崩、不会伪造时间：无法得知的提交不会凭空生成时间戳。

## 新赛制规则的实现

完整形式化说明与测试用例对照见 [`docs/rules.md`](docs/rules.md)。要点：

1. **题号揭示**：某题的过题队伍数达到 `max(⌊N × 20%⌋, 50)` 时，该题题号才出现在榜单上；此前列头显示 `?`。`N` 默认取榜单全部队伍数，可在网页上切换为「仅官方队伍」。
2. **题目排序**：每支队伍**各自**的列顺序 —— ① 已显示题号的题按题号升序；② 其余中该队已 AC 的按 AC 时刻升序；③ 其余中提交过的按最晚提交时刻升序；④ 从未提交的按题号升序排在最后（同样不显示题号）。
3. **AC 后忽略**：队伍 AC 某题后，对该题的再次提交被完全忽略 —— 不增加提交次数，也不影响排序。
4. **罚时**：首次 AC 的（按 `timePrecision` 取整的）时刻 + 每次计入罚时的失败提交 × 20 分钟。哪些结果计入罚时以榜单文件里 `sorter.config.noPenaltyResults` 为准。
5. **封榜**：按 `frozenDuration` 冻结，或按你的选择全程实时；结束后可揭榜。

### 一个需要注意的实现细节

榜单文件里的 `problems[].statistics.accepted` 是**发布时的快照**，可能与回放统计出的「实时过题队伍数」不一致（例如评测重跑导致官方统计与提交列表不同步）。

- **题号揭示**严格按回放得到的实时过题队数判断 —— 这才是「现场看榜」的正确语义。
- 列头下方显示的过题数是**官方快照值**，仅作参考。

以 2026 CCPC 网络预选赛为例：问题 M 官方统计 423 队（低于门限 434，看似永不显示），但逐条回放到达 434 队时会正常揭示。

### 排名并列

按 ICPC 规则，先比 AC 数，再比总罚时，最后比最后一次 AC 的时间。

实测发现 RankLand 官方榜单在「AC 数与总罚时都相同」的并列组内，顺序并不总是遵循最后一次 AC 时间。本工具在并列组内按最后一次 AC 排序，因此并列组之间的名次可能与官方榜单顺序略有差异 —— **分数完全一致，只是并列内部顺序不同**（回归测试已断言到「每个名次上的 (AC 数, 罚时) 与官方逐个吻合」这一强度）。

## 正确性验证

核心保证：**时间轴回放能逐队复现官方榜单**。

```bash
nix run .#test-e2e     # 或 VP_E2E=1 node --test test/e2e.test.mjs
```

对 **2026 CCPC 网络预选赛**（2170 队 / 30963 条提交）验证：

- 每队 AC 数、总罚时与官方榜单 **0 处不一致**；
- 每个名次上的 (AC 数, 罚时) 与官方逐个吻合；
- 快照加速回放在 7 个时间点上与从头回放完全一致；
- 旧格式场次（2017 CCPC 秦皇岛）降级后 AC 数仍与官方一致。

离线测试（`npm test` / `nix run .#test`）覆盖：SRK 解析与单位换算、规则 1–4 的每个分支、封榜与揭榜的边界、会话时钟的暂停/倍速/跳转、缓存与静态服务的路径安全、榜单单元格与列顺序的一致性。

### 界面验证

榜单渲染用真实数据在无头 Firefox 中实际截图核对过（`ccpc2026preliminary`，t=1000s 与 t=16000s），确认：

- 列头始终按题号顺序，未揭示的题显示 `?` 且不泄漏颜色；已揭示的题显示底色与该题当前过题数；
- 同一场里不同队伍的列顺序确实不同（例如 t=16000s 时，已全部揭示了可显示题号的强队会把隐藏题排在后面，而未揭示题的格子照样显示绿/红/黄）；
- 名次、队名、学校、题数、罚时五列固定左对齐且不随横向滚动移动；
- 绿色已解决格子显示「用时(罚次)」，红色未解决显示「-提交数」，黄色表示该题当时仍被冷冻。

> 由于本仓库里没有任何前端框架与构建步骤，无头浏览器验证走的是一个开发期辅助路径：`CCPC_NEO_VP_HARNESS=1` 会开放 `/__harness/<name>.html`（仅读取 `.dsh-tmp/`，默认关闭；见 `test/timeline.test.mjs` 的断言）。

## 项目结构

```
server/
  index.mjs          HTTP 服务、路由、CLI、keep-alive 调优
  rankland.mjs       RankLand 只读客户端（超时/退避重试）
  build-timeline.mjs SRK → 紧凑「时间轴」（两种格式都处理）
  cache.mjs          原子写磁盘缓存
  assets.mjs         静态资源服务（含路径穿越防护）
shared/              同构模块：Node 与浏览器共用
  srk.mjs            单位换算、结果码、文本提取
  rules.mjs          新赛制规则（揭示/排序/计分/排名）纯函数
  replay.mjs         回放控制器、快照加速、封榜解析
  live.mjs           VP 会话时钟（倒计时/暂停/倍速/跳转）
web/                 无构建步骤的前端
  index.html  ui.css
  app.mjs            界面状态机与交互
  board.mjs          行虚拟化的榜单渲染
test/                node:test 测试 + fixtures
docs/rules.md        规则形式化说明与测试对照
```

### 前端为什么不用框架

没有 `dependencies`、没有打包步骤：浏览器直接加载原生 ESM（`/app/*`、`/shared/*` 由同一个 Node 服务提供），榜单用行虚拟化渲染 2700 行也不掉帧。符合「个人自用、保持简单、只有 node 环境也能跑」的目标。

## FAQ

**点了「加载并开始」后提示「加载失败：The operation was aborted.」？**
已修复，原因有两个，都出在自己实现 HTTP 细节上：
1. 旧版本把整个下载包在一个 60 秒的 `AbortController` 总时长里，慢速线路下载 2.5 MB 榜单会被中止；
2. 旧版本手工设置了 `Content-Encoding: gzip`，并且 Node 默认的 keep-alive 只有 5 秒 —— 浏览器可能刚好选中一个即将被关闭的连接，请求就一直没有回音，最终被浏览器自己中止。

现在：总时长超时改成「连接超时 + 读取停滞」两个看门狗；JSON 响应不再手工压缩（本机回环上约 0.8 MB，无所谓），前端也不再手工解压；keep-alive 调高到 130 秒。请更新到最新提交后重启。

**我该怎么确认这次真的好了？**
在真实浏览器里实测过：加载榜单 + 渲染出榜单 **801 ms**（无中止、无报错）。你也可以自己看：启动时会打印自检地址。

**下载很慢 / 一直转圈？**
放宽超时重启：`RL_CONNECT_TIMEOUT_MS=60000 RL_STALL_TIMEOUT_MS=120000 nix run . -- --verbose`，同时打开 `/api/diagnose?uk=<比赛>` 看是哪一步慢。榜单文件约 2.5 MB。

**榜单不动 / 一直显示 0:00:00？**
比赛时间在倒计时结束前是负数，进入倒计时页是正常的。若长时间没反应，看终端是否有报错。

**为什么有的题号一直不显示？**
说明该题过题队伍数始终没到门限。这是新赛制的预期行为。

**为什么每支队伍的题目顺序看起来不一样？**
规则如此（新赛制刻意打乱，避免从列位置推断题号）。列头始终按题号顺序排列，行内顺序则因队而异。

**时间对不上真实比赛？**
VP 的时间轴按榜单文件里的比赛时长从头播放，与原始比赛的实际日期无关。

**旧场次的题目排序不对？**
该场榜单文件不含提交时间轴，规则 3 降级为按题号排序，页面顶部有「排序降级」提示。

**能换数据源吗？**
可以，`--base-url` 或 `RL_BASE_URL` 指向兼容的 RankLand 部署。
